# 指定版式的公文 Word 排版

用于已起草正文的排版与交付；内容写作沿用 official-document-writing。当前用户明确的本次格式要求优先。默认不改写事实、数字、标点或编号，不自动添加红头、文号、日期和落款。

## 默认版式

- A4；上下左右页边距均为25mm；所有段落固定行距28磅，段前段后0。
- 文章标题：方正小标宋_GBK，20磅，居中。
- 一级标题：方正黑体_GBK，三号16磅，不额外加粗。
- 二级标题：方正楷体_GBK，三号16磅，加粗。
- 三级标题：方正仿宋_GBK，三号16磅，加粗。
- 正文中文：方正仿宋_GBK，三号16磅，常规；两端对齐，首行缩进2字。
- 各层级中的英文、数字及ASCII符号（含%）用Times New Roman，字号和加粗跟随所在段落；中文标点使用相应中文字体。
- 一级、二级标题：首行缩进2字符；三级标题保持原有不缩进。正文取消孤行控制。
- 双引号（中文“ ”或英文直引号）及其中内容使用正文格式：中文为方正仿宋_GBK 16磅不加粗，英文和数字为Times New Roman 16磅不加粗，引号符号本身为方正仿宋_GBK；不转换或改写原文引号。引号必须在同一段落内配对，否则报告并请用户核实。
- 页脚居中，形式为“— 1 —”“— 2 —”；全部页码字符用四号（14磅）宋体，使用自动PAGE域。重新打开、打印或更新域后由Word/WPS计算页码。
- 用户要求同一篇稿件的全部生成文件（包含草稿、过程稿和最终稿）存放在指定公文输出目录（默认 E:\AI\公文输出\<文稿标题>\ 或用户当前提示词指定的输出路径）内。生成前以文稿标题作为单个目录名，安全替换 Windows 文件名禁止的字符，去掉尾部空格和点，防止空名、保留名与路径穿越。若目录已存在，不覆盖任何已有文件；为本次任务使用不冲突的目录名或文件名。
- 该路径可能在会话工作区外：创建目录及写入均须遵守DSH沙箱与审批。若未获授权或写入失败，明确告知用户，询问用户如何授权或更换目录；不要绕过限制，不要声称已保存，也不要静默改到别处。样式测试文件不属于用户公文输出。

## 执行

1. 如未加载，调用 office-docx；调用 load_workspace_dependencies，使用返回的 Python 和现有 python-docx，不安装第三方包。脚本位于本技能目录的 format_document.py。技能由插件注册时，目录将显示在资源位置中。
2. 先按上述规则确定并获得授权创建本次稿件目录。可使用受控 UTF-8 Markdown 或 JSON 输入；Markdown 第一行“# 文章标题”，标题用“## 一、一级标题”“### （一）二级标题”“#### 1.三级标题”，其余正文以空行分隔自然段，单换行表示同段内换行。标题编号由原文提供，脚本不编造。不要输出Markdown加粗标记、代码块、表格、图片或链接语法。
3. 同段混排标题与正文可用 JSON 的 {"type":"heading2","heading":"（一）标题。","body":"正文"} 表达，标题与正文须与原文完全一致，不插入空格或标点。已有 DOCX 使用本目录 preserve_docx.py 的独立保结构路径，不能通过新建文档的 format_document.py 重建。DOC/WPS 自动转换目前关闭，请用户先另存为 DOCX 副本。
4. PowerShell调用示例（替换实际Python、技能目录及文件路径）：

   & "<Python绝对路径>" "<本技能目录>\format_document.py" --input "E:\AI\公文输出\<文稿标题>\草稿.md" --output "E:\AI\公文输出\<文稿标题>\成稿.docx"

   署名、日期、主送机关可使用JSON输入：{"title":"标题","blocks":[{"type":"recipient","text":"各有关单位："},{"type":"body","text":"正文"},{"type":"heading1","text":"一、标题"},{"type":"signature","text":"已提供的署名"},{"type":"date","text":"已提供的日期"}]}。类型还包括heading2、heading3。
5. 脚本默认不覆盖已有输出；使用新的文件名。除非用户明确同意，不添加--overwrite。输入与输出不能同路径。一次性覆盖可传 --config-json，例如 '{"line_spacing_pt":30,"styles":{"body":{"font":"宋体","size_pt":16}}}'；支持四边 *_margin_mm、latin_font、各段样式 font/size_pt/bold。复检时必须提供同样的配置；不得静默读取目录中的配置。
6. 新建文档路径执行 --check "<生成的DOCX>" --input "<原输入>"，核对格式并逐段比对解析后的标题、正文文字和顺序，包含数字、标点和混排文字。生成时也会自动比对。此检查不验证内容真实性，也不证明Word/WPS实际分页完全一致。保结构路径使用其自身的结构核验与报告，不调用这个新建文档专用检查器。失败时先修复，不声称生成成功。
7. 如具备渲染能力，按office-render检查排版；报告缺字或字体替代，不自行替换用户指定字体。最后通过present交付实际DOCX并简述验证状态。仅在成功执行后报告文件已生成。

## 已有 DOCX 保结构排版

使用 `preserve_docx.py --input "<原稿.docx>" --output "<新稿.docx>"`；输出必须是新文件，不能覆盖原稿或已有文件。可用 `--config-json` 覆盖字体、字号、加粗和行距；保结构模式不支持页边距覆盖，显式传入会报错。先依据原稿样式与明确的大纲信息识别标题，不能盲目将普通编号断定为标题。该路径保留原纸张、分节、页眉页脚及页码，不保证符合上述新建文稿的页面和页码默认值；表格、图片、复杂对象以及不安全的段落按报告保留原样。逐项审阅成功结果中的 status、formatted、skipped、preserved、verification 和 limitations；status 为 no_changes 时说明没有完成任何段落排版，未处理或有歧义的段落向用户说明，不能声称整篇均已排好。验证失败不得交付。按需渲染并检查图片、表格、字体替代和分页；内容一致性与结构核对不等同于实际视觉效果完全一致。

## Token与上下文

仅在需要Word排版时加载本技能；普通正文写作不需要加载。技能加载内容仍进入模型上下文并可能计费，不承诺零Token或固定折扣。

## 智能体协作

- 默认由主智能体独立完成排版、核验和交付；常规步骤不得启动并行智能体或工作流。
- 并行是显式选择：只有存在可独立验收的子任务，且用户明确要求或同意后，才启动子智能体。否则按顺序处理。
- 单次任务最多并行2个子智能体；推理档位默认 `low`。需要更高档位或更多智能体时，先向用户说明原因并取得明确同意；不因任务复杂就自动提高档位或扩容。
- 每个子智能体仅提供其子任务必需的目标、文件路径、约束和验收要求。不得传入完整对话、无关文件、完整主会话历史或敏感数据。
- 主智能体只吸收简短结果：结论、涉及文件、验证结果和未解决事项。不要把子智能体的完整推理过程、工具轨迹或原始日志粘回主会话；主智能体应自行核验关键结论。
